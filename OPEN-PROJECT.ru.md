# Открыть и изменить полный проект

В `UnityProject` находятся сцены, модели классической игры, текстуры, материалы,
префабы, UI, данные всех рас, код, Packages и ProjectSettings. Это полный проект
для Unity 6000.6.4f1. Все исходные пути и GUID сохранены. Кэши Library, готовые
Builds, личные настройки и ключи подписи в репозиторий не входят.

Тяжёлые анимации и архивные исходники Reforged хранятся в ZIP-пакетах Releases
этого же репозитория. Список файлов и SHA-256 находится в `unity-assets.json`.
LFS и платная подписка для загрузки этих пакетов не нужны. Восстановленный
проект занимает около 38 ГиБ; Unity отдельно создаст Library при импорте.

## Подготовка с другого компьютера

1. Клонируйте `https://github.com/boltongenry-ops/Castle-fight.git`.
2. Установите Python 3.10+ и выполните из корня репозитория:

   ```powershell
   python tools/unity_assets.py restore
   ```

3. После завершения откройте папку `UnityProject` в Unity Hub редактором
   6000.6.4f1. Unity создаст собственный Library и импортирует ассеты. Не
   открывайте редактор до завершения восстановления: это может создать
   ненужные новые файлы вместо отсутствующих ресурсов.
4. Откройте `Assets/Scenes/CastleFightMap.unity`. Для проверки игры нажмите Play.

Восстановление проверяет контрольные суммы и продолжает прерванную загрузку.
Существующие изменённые файлы оно не перезаписывает. Скачанные ZIP остаются
в `.asset-cache`; после успешной подготовки этот кэш можно удалить.

## Где менять

- `UnityProject/Assets/SourceAssets/models_lines` — классические исходные модели;
- `UnityProject/Assets/SourceAssets/pcui` — иконки и элементы интерфейса;
- `UnityProject/Assets/GeneratedPC` — игровые префабы, материалы и анимации;
- `UnityProject/Assets/Resources` — каталоги рас, игровые наборы и общие ресурсы;
- `UnityProject/Assets/Structure031` — актуальная дополнительная версия панд;
- `UnityProject/Assets/Scenes` — сцены;
- `UnityProject/Assets/Scripts` — механики и интерфейс;
- `source/Launcher` — лаунчер.

Модели, текстуры и другие двоичные файлы заменяются через Unity/3D-редактор и
коммитятся вместе с соответствующими `.meta`. GitHub позволяет загрузить
заменяющий файл, но сам не является редактором 3D-моделей. Сохраняйте `.meta`
при замене существующего файла, иначе потеряются ссылки на него. После замены
исходного GLB обновите соответствующий игровой префаб и платформенные
пакеты моделей перед выпуском.

Изменения обычных файлов фиксируются стандартным `git add`/`git commit`.
Если изменены анимации или архивные Reforged-исходники, подготовьте новые пакеты:

```powershell
python tools/unity_assets.py pack-changes --tag unity-assets-MY-VERSION
```

Команда создаст ZIP в `asset-packs` и обновит `unity-assets.json`. Сначала
загрузите новые ZIP в GitHub Release с указанным тегом, затем коммитьте индекс.
Старые пакеты не удаляйте: на них могут ссылаться другие версии проекта.
`python tools/unity_assets.py verify` проверяет восстановленные внешние ассеты.

## Сборка и выпуск

Редактирование исходников не меняет опубликованный EXE/APK автоматически.
После правок нужно собрать и проверить игру в Unity, загрузить новые файлы
в Release и последним обновить корневой `release.json`. Именно этот файл читает
лаунчер. `unity-assets.json` обслуживает исходный проект и не является
каталогом игровых обновлений.

Сцену карты можно собрать для Windows через Build Profiles. Исторические
скрипты регенерации ассетов в Assets/Editor могут обращаться к локальным
архивам Warcraft/Godot; для открытия и редактирования уже перенесённых моделей
эти архивы не нужны. Для Android нужны Android Build Support/SDK/NDK; ключ
подписи опубликованного приложения намеренно хранится отдельно, а не в GitHub.
