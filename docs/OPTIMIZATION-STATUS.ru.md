# Состояние оптимизации 0.35 — 17 ноября 2026

Общий код включён в Windows и Android 0.35/code23. Этот этап сохраняет стоимость, производство, лимиты, частоту шага и порядок боевых действий. Нативный сервер этим выпуском не меняется; ускоряется локальная симуляция боя с ботом. Сетевой клиент получает тот же код и интерфейс, но скорость серверного расчёта от замены APK не изменяется.

| Область | Реализовано |
|---|---|
| Пространственные запросы | Переиспользуемые ячейки; отдельная сетка соседей GroundSeparation; локальные цели/ассасины/заклинания. Стабильный исходный порядок, обновление при перемещении, рождении и телепортации |
| Источники и производство | Отрицательный кэш связей стихий с повторной проверкой живых источников; фазовый счёт армии вместо полного скана у каждого заблокированного производителя |
| JSON и способности | Типизированные горячие свойства, инвалидируемый кэш активных/пассивных способностей; ручные горячие циклы статусов/яда с сохранением рангов |
| Временные снимки | 81 ToArray заменён вложенными переиспользуемыми снимками; ячейки возвращаются в пул и очищают ссылки |
| События | Очередь отложенных HumanJob, сохраняющая float countdown, исходный порядок и переменный dt |
| Jobs/Burst | Независимые числовые задачи радиусов аур и плотности целей; строгая арифметика, порог размера, скалярный путь для небольших наборов |
| Настройки Android | Единая высота строк и раздельный нижний блок скачивания/обновления/отмены/применения |

Все таймеры в очередь не переводились: эффекты урона/регенерации должны обновляться каждый шаг; производство продолжает показывать актуальное оставшееся время. Неблокированные 1000 производителей без армии занимают около 4 мс/шаг в этом тесте; для них новый кэш не даёт ускорения. Перенос зависимого движения в параллельные задачи и снижение частоты решений не применены: это отдельные изменения поведения. Полного ECS-перехода и нулевых выделений памяти нет.

## Измерения фактического portable

Одинаковый Windows Mono player, настоящая выпущенная DLL 0.34 загружается рядом с новой через переименование сборки. По 24 чередующихся замера одинакового шага; без отрисовки в измеряемом интервале. Это миллисекунды CPU на шаг, не FPS и не замеры телефона. 1000/2000 юнитов — искусственная нагрузка сверх обычного лимита. Ауры/удары в плотном контакте создают тяжёлые пики, которые этот этап полностью не устранил.

| 320 / dense_contact | 64.30 → 37.22 | 162.48 → 142.86 | 279.80 → 246.71 |
| 1000 / separated_march | 1173.50 → 270.54 | 1442.45 → 323.59 | 1510.60 → 341.04 |

1000 производителей при заполненной армии: p50 184.74 → 38.76 мс. Без армии: 3.45 → 3.99 мс; этот случай немного замедлился. Это общий шаг, включающий движение армии, а не изолированный таймер производства. Счётчик GC.Alloc/managed thread bytes в этом Mono player недоступен; в отчёте null, а не утверждение о нулевом GC.

## Проверки и оставшаяся работа

Конечный portable: 127 проверок оптимизации/интерфейса, пошаговый паритет 16 рас с 0.34, 71 проверка нерубов, 28 тумана, 104 испытаний, старт всех 30 раундов. Проверены вложенные снимки, мутации JSON и состава способностей, переменный dt, порядок целей и скалярный паритет Jobs. Сохранены раскладки 118 прежних типов и исходные ресурсы player; заменены DLL игры и её нативный Burst-плагин. Обе платформы собраны из одних 187 runtime-исходников. Android: прежняя подпись/package, code23, те же 33 пакета контента. Физическая производительность Android не измерена. Пользователь подтвердил устранение вылета Ultimate в 0.34.

Крупные армии всё ещё дорогие: следующий этап — профилировать зависимые решения/движение и пиковые цепочки ударов, потом отдельно менять алгоритм с контролем паритета. Полный план исследований не объявляется завершённым. Отчёты: Validation/Optimization035/portable и Validation/Android035; исходные JSON измерений поставляются в docs/optimization035.
