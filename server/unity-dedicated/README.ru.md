# Unity-сервер Castle Fight

Процесс Unity запускает общий расчёт `HumanMatch` с двумя управляемыми игроками. Шлюз принимает WebSocket-соединения, ведёт список игр и комнаты, проверяет слот игрока и сохраняет возможность переподключения. Доступ к Unity-процессу идёт через HTTP на loopback с отдельным ключом.

Сцена сервера пустая. Метод `BuildDedicatedCastleFight.Linux` собирает Linux Dedicated Server под версию Unity из `ProjectVersion.txt`. Сборка использует те же скрипты, что версия игры. Перед запуском передайте каталоги `race-*.json`, выгруженные из `PcGame.RaceCatalog` для тех же исходников и ресурсов. У каталога людей должно быть имя `Human Alliance`.

Шлюзу нужен Python 3.10 или новее и пакет из `requirements.txt`. Unity и шлюз получают одинаковые `CF_AUTHORITY_KEY` и `CF_AUTHORITY_PORT`. Директория каталогов задаётся через `CF_CATALOG_DIR`, порт шлюза — через `CF_GATEWAY_PORT`. Публичный TLS завершается на обратном прокси. Порт HTTP-расчёта доступен только через loopback.

Для интеграции с существующими аккаунтами и голосом задаются `CF_PROFILE_PORT`, `CF_PROFILE_SECRET`, `CF_RESULT_DIR` и `CF_VOICE_URL`. Результаты хранятся локально до приёма сервисом профилей. Секреты хранятся вне Git.

Главная точка входа клиента в тестовый режим — URL `wss://45-15-156-101.fatmetal.net/play-unity-preview`. Проверка совместимости протокола требует `authority: 1` при подключении. Перед основным выпуском требуется проверить полный матч с двух игровых клиентов, бой с большим числом юнитов, туман войны, боевые эффекты и работу профилей и голоса на обеих платформах.
